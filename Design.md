# Design — agent-receipts

agent-receipts has three surfaces: the **terminal** (`scan`, `ls`), the **Markdown PR comment**, and (Phase 4) a **self-contained HTML receipt**. The visual idea is a *till receipt*: compact, monospaced numbers, one clear verdict at the top, line items below.

## 1. Colour palette

| Token | Light | Dark | Use |
|---|---|---|---|
| `--bg` | `#FAFAF7` | `#111214` | Page background (warm paper / near-black) |
| `--surface` | `#FFFFFF` | `#1A1C1F` | Cards, receipt body |
| `--border` | `#E4E2DC` | `#2C2F33` | Dividers, table rules |
| `--text` | `#1B1C1E` | `#E8E8E6` | Primary text |
| `--text-muted` | `#6B6E73` | `#9A9DA3` | Timestamps, secondary |
| `--accent` | `#3B5BDB` | `#7C93F5` | Links, focus ring, brand |
| `--verified` | `#2B8A3E` | `#51CF66` | VERIFIED |
| `--stale` | `#B26A00` | `#FFB84D` | STALE |
| `--failed` | `#C92A2A` | `#FF6B6B` | FAILED / critical |
| `--unverified` | `#5F6B7A` | `#A5B1C2` | UNVERIFIED |
| `--sev-high` | `#D9480F` | `#FF8A4C` | High severity |
| `--sev-medium` | `#B08900` | `#F2C94C` | Medium |
| `--sev-low` | `#1971C2` | `#74C0FC` | Low / info |

Status is **never** conveyed by colour alone — always paired with a label and an icon glyph (✔ VERIFIED, ◷ STALE, ✖ FAILED, ? UNVERIFIED).

Terminal (Rich) mapping: verified → `green`, stale → `yellow`, failed → `bold red`, unverified → `grey58`, accent → `blue`. Respect `NO_COLOR` and `--no-color`.

## 2. Themes

- HTML: CSS custom properties on `:root`, dark values under `@media (prefers-color-scheme: dark)` and `[data-theme="dark"]`; a toggle stores choice in `localStorage` (wrapped in try/catch).
- Markdown: no custom colours (GitHub controls them) — use emoji-free text badges and GitHub alert blocks (`> [!WARNING]`) for high/critical findings so they render in both GitHub themes.

## 3. Typography

| Role | Font | Fallback |
|---|---|---|
| UI / headings | **Inter** | `system-ui, -apple-system, Segoe UI, sans-serif` |
| Code, commands, numbers | **JetBrains Mono** | `ui-monospace, SFMono-Regular, Menlo, monospace` |

Scale (1.25 ratio, base 16px): `12 / 14 / 16 / 20 / 25 / 31` px. Line-height 1.5 for body, 1.25 for headings. Numbers use `font-variant-numeric: tabular-nums`. Headings weight 600, body 400; never below 12px.

## 4. Spacing & layout

4px base grid: `4, 8, 12, 16, 24, 32, 48`. Receipt column max-width `760px`, centred; 16px side gutter on mobile; radius `8px` for cards, `4px` for badges; borders 1px.

## 5. Components

| Component | Spec |
|---|---|
| **Verdict banner** | Full-width strip at top: glyph + status word (20px/600) + one-line reason (14px muted). Background = status colour at 10% opacity, left border 4px solid status colour. |
| **Stat row** | 4 tiles: Files changed · Commands run · Findings (by severity) · Tokens. Number 25px mono, label 12px muted uppercase. |
| **Findings table** | Columns: Severity badge · Rule id (mono) · What happened · Step #. Sorted critical → info. Max 10 rows, then "+N more" `<details>`. |
| **Timeline** (HTML) | Vertical list of events; edits = pencil glyph, checks = flask glyph, risky = triangle glyph; last edit and last check visually connected with a bracket to explain the verdict. |
| **Severity badge** | Uppercase 11px/600, padding 2×6px, radius 4px, text in severity colour on 12%-opacity fill. |
| **Usage block** | Tokens per model and MCP/tool counts as a two-column key–value list. |
| **Footer** | `generated by agent-receipts vX · receipt sha256:… · head abc1234` in 12px mono muted. |

### Markdown PR comment layout

```
<!-- agent-receipts -->
### 🧾 Agent receipt — ✔ VERIFIED
Tests ran after the final edit and passed (`pytest -q`, step 84).

| Files | Commands | Findings | Tokens |
|---|---|---|---|
| 7 | 23 | 1 high · 2 low | 412k |

> [!WARNING]
> **GIT002 · high** — `git push --force` on step 61

<details><summary>Assumptions (3) · Tools & MCP (5) · Sessions (2)</summary> … </details>
```
(The single 🧾 is the only emoji used — as a stable visual anchor for the comment.)

## 6. Accessibility

- WCAG 2.1 AA contrast: all text tokens ≥ 4.5:1 on their background; status colours checked against `--surface` in both themes.
- Status always has text + glyph, not only colour (colour-blind safe).
- HTML: semantic `<table>`, `<details>`, landmarks (`<header>`, `<main>`, `<footer>`), visible `:focus-visible` ring in `--accent` 2px.
- Respect `prefers-reduced-motion` (no animated timeline).
- Terminal: honour `NO_COLOR`; `--plain` output for screen readers and logs.
- Keep PR comments under ~60 lines by default; long detail goes into collapsible sections.
